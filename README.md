CS 465 Module Eight Journal Reflection
Architecture

In this full stack application, I worked with multiple types of frontend development approaches including Express HTML, JavaScript, and a Single Page Application (SPA). The Express HTML portions were primarily used for server-rendered pages that load fully from the backend. JavaScript was used to add interactivity, dynamic behavior, and handle client-side logic. The SPA portion improved user experience by allowing smoother navigation and faster updates without requiring full page reloads.

Each approach served a different purpose: Express HTML was more traditional and simple to implement, while the SPA provided a more modern, app-like experience. Combining these approaches allowed the application to be both functional and user-friendly.

The backend used a NoSQL MongoDB database because it offers flexibility with data structures. Unlike relational databases, MongoDB stores data in JSON-like documents, which makes it easier to scale and adjust schemas as the application evolves. This was especially helpful for handling dynamic or changing data requirements throughout development.

Functionality

JSON (JavaScript Object Notation) is a lightweight data format used to exchange information between the frontend and backend. While JavaScript is a programming language, JSON is simply a structured format for storing and transmitting data. JSON acts as the bridge between the frontend and backend by allowing data to be sent through API requests and then interpreted by JavaScript on the client side.

During development, I refactored code to improve readability, reduce repetition, and improve performance. For example, I consolidated repeated UI components into reusable functions and standardized API calls. This improved efficiency by making the code easier to maintain and update.

Reusable UI components provide several benefits, including consistency across pages, reduced development time, and easier debugging. Instead of rewriting similar code multiple times, components can be reused wherever needed, making the application more modular and scalable.

Testing

In a full stack application, methods such as GET, POST, PUT, and DELETE are used to interact with API endpoints. Each endpoint handles a specific type of request, such as retrieving data, creating new records, updating existing data, or deleting entries.

Testing these endpoints is important to ensure that the application behaves correctly. Tools like Postman or browser developer tools can be used to verify that requests return the correct responses.

Security adds another layer of complexity to testing because some endpoints require authentication. In this project, secure login authentication was implemented for admin access, meaning certain API calls could only be made with valid credentials or tokens. This requires testing both authorized and unauthorized scenarios to ensure the system properly protects sensitive data.
